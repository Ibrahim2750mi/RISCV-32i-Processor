## About the Project

This project implements a **32-bit RISC-V processor** targeting the **RV32I Base Integer Instruction Set** in Verilog HDL. The design is based on the architecture described in:

> Manjusha Rao P, Prabha Niranjan, Dileep Kumar M J,  
> *"Design and Implementation of 32-bit RISC-V Processor using Verilog"*,  
> 2024 IEEE International Conference on Distributed Computing, VLSI, Electrical Circuits and Robotics (DISCOVER), pp. 181–186.  
> DOI: [10.1109/DISCOVER62353.2024.10750638](https://doi.org/10.1109/DISCOVER62353.2024.10750638)

The processor executes one instruction per clock cycle, with all datapath components operating in a single pass: **Instruction Fetch → Decode → Execute → Memory → Write-Back**.

---

## Architecture Overview

The single-cycle datapath is organized around the following signal flow (Figure 5 in the referenced paper):

```
PC → Instruction Memory → Decoder
                               ↓
              Control Unit ← opcode/funct3/funct7
                               ↓
         Register File → ALU → Data Memory → Write-Back MUX → Register File
                   ↑                                              |
               IMM_GEN ←── instruction[31:0]                     |
                                                          rd ← result
```

Key design decisions matching the paper:
- **Harvard-inspired fetch**: instruction and data share one external memory bus (per project interface), with the processor managing the two-phase access internally.
- **Single-cycle execution**: no pipeline registers; every instruction completes in one clock.
- **Modular Verilog**: each functional unit is an independent module, matching the sub-unit structure of the reference implementation.

## Sub-Module Descriptions

### ALU (`ALU.v`)
Performs all arithmetic and logic operations. Supports: ADD, SUB, AND, OR, XOR, SLL, SRL, SRA, SLT, SLTU. Outputs a `zero_flag` used by the branch unit.

### CONTROL (`CONTROL.v`)
Fully combinational decoder. Reads `opcode`, `funct3`, and `funct7` to drive every datapath mux and enable signal. Outputs: `alu_control`, `alu_src`, `regwrite`, `mem_read`, `mem_write`, `mem_to_reg[1:0]`, `branch`, `jump`, `jalr`, `auipc`, `lui`.

### BRANCH_UNIT (`BRANCH_UNIT.v`)
Evaluates branch conditions (BEQ, BNE, BLT, BGE, BLTU, BGEU) using `funct3` and the ALU result. Returns a single `branch_taken` signal to the PC mux.

### REG_FILE (`REG_FILE.v`)
32 × 32-bit registers. Asynchronous reads, synchronous writes on `posedge clk`. Register `x0` is hardwired to zero and cannot be overwritten.

### IMM_GEN (`IMM_GEN.v`)
Sign- (or zero-) extends immediates for I, S, B, U, and J instruction formats using the opcode to determine the format.

### LOAD_EXTRACTOR (`LOAD_EXTRACTOR.v`)
Extracts the correct byte/half-word/word from a 32-bit memory word and applies sign or zero extension based on `funct3` (LB/LH/LW/LBU/LHU).

### STORE_UNIT (`STORE_UNIT.v`)
Generates the 32-bit aligned write data and 4-bit byte-enable mask for SB/SH/SW, using `byte_offset = mem_addr[1:0]`.

## Tools Used

### [iVerilog](https://github.com/steveicarus/iverilog)
Open-source Verilog compiler and simulator. Recommended for compilation and simulation of all modules.

### [GTKWave](https://gtkwave.sourceforge.net/)
Waveform viewer for `.vcd` files generated by the testbenches. Essential for signal-level debugging.

## Getting Started

### Prerequisites
```sh
sudo apt install iverilog gtkwave   # Debian/Ubuntu
brew install icarus-verilog         # macOS
```

### Loading a Program
The processor fetches instructions from an external memory. For simulation, the `Processor_tb.v` testbench pre-loads instructions inline using a `load_word` task. For FPGA or hex-file-based simulation, populate `program.hex` in the working directory.

### Compiling

```sh
cd Processor
iverilog -o riscv_sim Processor_tb.v
```

### Running

```sh
vvp riscv_sim
```

### Viewing the Waveform

```sh
gtkwave processor_output_wave.vcd
```
